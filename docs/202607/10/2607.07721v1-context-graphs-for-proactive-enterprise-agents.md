## 摘要
检索增强生成（RAG）和智能体框架显著推动了企业级人工智能的发展，但智能体本质上仍然是被动的：它们在采取行动之前需要等待人类查询。本文认为，真正的企业生产力提升需要主动智能体：即在员工提问之前就向其展示相关且可操作的信息的系统。我们提出了上下文图（Context Graph），一种实时关系型数据结构，用于对企业实体、实体间关系以及随时间发生的状态变化进行建模。基于该图，我们定义了增量检测引擎（Delta Detection Engine），用于持续监控状态变化；主动性评分器（Proactivity Scorer），根据紧迫性、相关性和角色适配度对候选洞察进行排序；以及由大语言模型（LLM）驱动的展示层（Surfacing Layer），用于提供带有可靠解释的排序通知。我们对各个组件进行了形式化描述，推导出了统一的主动性评分函数，并提供了使用NetworkX和Anthropic Claude API的完整端到端Python实现。在三个通用企业案例研究（合同生命周期管理、工程事件响应和销售管道健康度）中的评估表明，由上下文图驱动的主动性达到了0.83的前5位精确率（Precision@5）、0.11的假阳性率，并将平均展示时间从47分钟（被动基线）缩短至不到30秒。

## Abstract
Retrieval-Augmented Generation (RAG) and agentic frameworks have advanced enterprise AI considerably, yet agents remain fundamentally reactive: they wait for a human query before acting. This paper argues that genuine enterprise productivity gains require proactive agents: systems that surface relevant, actionable information to workers before they ask. We propose the Context Graph, a live relational data structure that models enterprise entities, their relationships, and state transitions over time. Built on this graph, we define a Delta Detection Engine that continuously monitors state changes, a Proactivity Scorer that ranks candidate insights by urgency, relevance, and persona-fit, and a Surfacing Layer powered by an LLM that delivers ranked notifications with grounded explanations. We formalize each component, derive a unified Proactivity Score function, and provide a complete end-to-end Python implementation using NetworkX and the Anthropic Claude API. Evaluation across three generic enterprise case studies (contract lifecycle management, engineering incident response, and sales pipeline hygiene) demonstrates that context-graph-driven proactivity achieves Precision@5 of 0.83, a false positive rate of 0.11, and reduces mean time to surface from 47 minutes (reactive baseline) to under 30 second.

### 2. 论文提出的方法论

论文提出了一个名为 **“主动展示系统”（Proactive Surfacing System）** 的完整框架，其核心是一个名为 **“上下文图”（Context Graph）** 的实时数据结构。

- **核心思想**: 使用一个动态的、带时间戳的有向属性图来建模企业实体（如人、任务、资产、系统等）及其关系。系统持续监控该图的状态变化（即增量事件），当检测到特定规则被触发时，会对该事件进行多维度评分，最后通过LLM生成一条自然语言通知，推送给最相关的用户。
- **关键技术细节**:
    1.  **上下文图 (Context Graph)**: 定义为一个带时间戳的有向属性多重图。节点代表企业实体（如任务、人员、合同），边代表关系（如`assigned_to`, `depends_on`, `blocks`）。每个节点和边都携带丰富的属性（如状态、截止日期、拥有者、关系权重等），并映射到一张表（Table 1 & 2）。
    2.  **增量事件模型 (Delta Event Model)**: 图中任何状态修改操作都会产生一个增量事件`δ = (entity_id, change_type, old_value, new_value, timestamp, clock)`。`change_type`包括状态转换、阈值突破、关系改变、过时和依赖风险。
    3.  **增量检测引擎 (Delta Detection Engine - DDE)**: 持续将每个增量事件与一组预先注册的**阈值规则 (Threshold Rules)** 进行匹配。当规则`r(G, δ) = True`时，DDE会生成一个**候选洞察 (Candidate Insight)**，其中包含一个2跳邻域的上下文快照（subgraph）。
        - **阈值规则示例**: R-01 (任务年龄 > SLA小时数), R-02 (资产到期日 < 7天), R-03 (任务状态为'blocked'且年龄 > 24小时)。
    4.  **主动性评分器 (Proactivity Scorer)**: 这是解决“告警疲劳”的关键。它为一个候选洞察`c`和一个用户`u`计算一个综合评分 `P(c, u)`，只有得分足够高的洞察才会被展示。公式如下：
        - **`P(c, u) = w1 · U(c) + w2 · R(c, u) + w3 · F(c, u) + w4 · K(c)`**
        - **紧迫性 `U(c)`**: 基于规则严重性和时间压力（距离截止日期）。
        - **相关性 `R(c, u)`**: 基于用户是否是任务的直接负责人、团队成员，或通过图的最短路径距离衡量关联度。
        - **角色适配度 `F(c, u)`**: 衡量洞察的类型是否与用户的角色（如工程师、法务）相符。
        - **置信度 `K(c)`**: 基于数据完整性和规则的过往精确率。
    5.  **LLM 展示层 (LLM Surfacing Layer)**: 接收排序后的顶尖洞察和其上下文快照。LLM（文中使用Anthropic Claude API）不负责推理图数据，而是负责将结构化数据**翻译**成易读、可操作的自然语言通知（包含标题、解释和行动建议）。系统还包含去重和冷却窗口机制。

- **算法/公式流程**:
    1.  **初始化**: 构建上下文图`G`，注册阈值规则`R`。
    2.  **监测**: DDE迭代所有节点，应用每条规则`r ∈ R`。
    3.  **检测**: 若`r(G, entity_id) = True`，则创建候选洞察`c`，并提取其k跳子图快照。
    4.  **评分**: 对于每个候选洞察`c`和用户`u`，计算主动性评分`P(c, u)`。
    5.  **过滤与排序**: 基于阈值`τ`和Top-K策略，选出`Surface(u)` = `top-k{c: P(c, u) >= τ}`。
    6.  **生成与推送**: 将`Surface(u)`中的每个洞察和其上下文传递给LLM，生成自然语言通知，并推送给用户`u`。
