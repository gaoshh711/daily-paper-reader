## 摘要
科学人工智能智能体能够自主执行复杂的研究工作流程，然而这些展开的工作流程往往难以让人类检查和评审，限制了可解释、可控且有效的人机协作。为了应对这一挑战，我们提出了一个监控与可视化框架，该框架记录细粒度的执行事件，并将其组织成有向图，使智能体工作流程在执行过程中变得清晰可见。该系统记录了中间步骤（如工具调用和代码执行），并以实时更新的可视化轨迹形式呈现，揭示工作流程结构。这使得用户能够检查结果是如何产生的，识别失败出现的位置，并更好地理解智能体在研究过程不同阶段的行为。我们针对跨学科背景（人工智能、神经科学和生物学）的领域专家，在复杂研究任务上进行了评估。专家报告称，结构化的轨迹可视化提高了对智能体工作流程的理解、感知的可解释性以及用于分析和进一步交互的可用性。

## Abstract
Scientific AI agents can autonomously carry out complex research workflows, yet these unfolded workflows often remain difficult for humans to inspect and review, limiting interpretable, controllable and effective human-AI collaboration. To address this challenge, we present a monitoring and visualization framework that records fine-grained execution events and organizes them into a directed graph that makes agent workflows explicit as they proceed. The system records intermediate steps (e.g. tool calls and code executions), and renders them as real-time updated visual traces that expose workflow structure. This allows users to examine how results are produced, identify where failures emerge, and better understand agent behavior across different stages of the research process. We conduct an evaluation on complex research tasks with domain experts of interdisciplinary backgrounds in AI, neuroscience, and biology. Experts report that structured traces visualization improves understanding of agent workflows, perceived interpretability, and usability for analysis and further interaction.

## 2. 论文提出的方法论

- **核心思想**：将智能体的执行过程抽象为结构化轨迹（structured execution traces），以有向图的形式呈现，节点代表原子子任务，边代表依赖关系（因果或逻辑顺序），而非单纯的时间顺序。通过分离任务执行模块与跟踪构建模块，保持框架对智能体平台的无关性。
- **系统架构（四个模块）**：
  1. **Scientific Agent**：负责自主执行研究任务并产生结果（文中使用OpenHands作为代表框架），通过MCP（Model Context Protocol）调用报告完成的子任务。该模块不直接构建图。
  2. **Monitor Agent**：接收Scientific Agent的报告，将其重构为标准化节点（根据预定义的节点模式），并确定节点间的父子关系。该代理封装为MCP兼容工具，实现即插即用。
  3. **Parser & Persistence Module**：执行模式约束验证（节点必须符合结构、父引用必须存在、不允许循环或孤儿依赖），仅将有效节点和边追加到“只增写入JSON账本”（append-only JSON ledger），保证结构完整性和真实性。
  4. **Frontend Visualization Module**：基于React的前端，将有向图实时渲染，支持拖拽、缩放、平移和最小地图导航，节点点击可显示元数据（描述、产物、依赖关系）。
- **关键技术细节**：Monitor Agent使用结构化提示来定义节点语义和父节点选择规则（基于逻辑研究合理性而非时间顺序）；Parser强制模式约束；可视化与后端状态保持同步，确保前后一致性。

- **UI设计**：三面板布局（对话、图可视化、节点详情）直观易用，支持实时交互和节点级审计，提升了用户体验。

## 8. 不足与局限

- **依赖智能体合规性**：框架要求Scientific Agent在恰当的语义边界调用MCP跟踪工具，若跳过或延迟调用，轨迹可能不完整或碎片化，质量依赖代理的协议遵守情况。
- **监控代理解释错误**：使用LLM将低级执行报告转换为高级子任务单元，仍可能误解歧义报告或引入幻觉结构，导致错误的任务分解或不准确的依赖链接。
- **大规模执行图的可扩展性**：极长工作流可能生成数百个节点，当前缺少层次化子图折叠、语义模块分组、渐进式节点展开等交互机制，增加用户认知负担。
- **实验局限性**：评估专家数量有限（5人），案例数量不多（7个），且未与其他可视化框架（如ReasonGraph）进行直接对比，结论的普适性需要更多大规模研究验证。
- **应用限制**：当前框架仅支持“查看”，不支持节点级回溯干预或根据专家反馈动态调整代理行为，未来需扩展交互能力。
